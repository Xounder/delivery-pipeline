## Must Not Change (Project-Wide Invariants)

These five invariants from `index.md` apply to every work item in this task. A change that cannot satisfy all five is out of scope and must be re-specified.

1. **Functionality** — no behaviour, no interaction, no animation timing, no data, no link target, no form semantics change. **`sameAs` URLs must be copied from the existing `iconsData.ts` `url` fields — do not author new URLs.**
2. **Visual branding** — rendered output must be pixel-identical. **Alt text changes are invisible when images render; they change the accessibility tree and SEO text. `W4.6` must not alter image dimensions or layout.**
3. **Copy** — all visible text, `alt` strings, `title`, `pattern`, JSON-LD field wording are unchanged. **`W4.6` is the explicit exception: it changes `alt` strings.** The plan's constraint (`feasibility.md`): alt text must be *derived from existing copy* — project names, role, company from `data.ts`. **W4.3's JSON-LD field values are likewise drawn from existing copy, not new prose.**
4. **Routing** — `/` and `/scroll` only, `vercel.json` untouched. **JSON-LD `url` fields must reference `/` and `/scroll` only.**
5. **DOM class names consumed by JS** — `.atual-section__content h2`, `.atual-section__content__icons`, `data-section`, `.group-cards`, `section` element names, `#root` may not be renamed. **W4.6's alt-text work must not change the `<img>` element's class names or `data-section` attributes.** The `:lang()` selector at `index.css:49` must keep matching the same elements.

**Explicitly out of scope:** W4.12 prerender tooling (TASK-22-adjacent, and OOS-6 says no prerender tooling in this plan), and any change to the `lang` attribute's *value* without confirming the site is actually Portuguese (see Edge Cases).

## Description

The metadata-semantics group. `feasibility.md` estimates the group at Medium effort, Medium risk.

**W4.3 — JSON-LD.** Add `Person` and `WebSite` structured data, wired from the existing data layer, with `sameAs` links pointing at the existing social URLs. Injected as a `<script type="application/ld+json">` block in `index.html`. `impact-analysis.md` notes the wiring cost: the Vite build does not template HTML, so a hand-written block in `index.html` cannot import from `src/`. **The block must therefore be either a static JSON literal, or generated by an in-app injection at mount — decide and record which.**

**W4.6 — alt text.** 11 images currently have generic or empty alt text. The plan classifies them:
- **Duplicated (D)** — `me.webp`, `github.svg`, `linkedin.svg` are duplicated across all 14 cards.
- **Content-bearing (B)** — `me.webp` and `lnkd.svg` carry real meaning.

`feasibility.md`: *"Duplicated decorative instances → `alt=""` + `aria-hidden`. Content-bearing → real alt."* The `me.webp`/`github.svg`/`linkedin.svg` overlap means **classification must be per usage site, not per asset.** W4.16 documents this convention.

**W4.9 — `<html lang>` and `:lang()`.** `index.html:2` declares `lang="pt-BR"`; `src/index.css:49` uses `:lang(pt-BR)`. If the site's visible copy is English, a `:lang(pt-BR)` selector may never match — a silent failure. Unify the two.

**W4.14 — prerender-readiness.** Land the metadata module the site will consume when prerender is added, so a future prerender step has one source of truth. **No prerender tooling in this plan (OOS-6).** This is a data module and a note, nothing more.

**W4.16 — documentation only.** Document the duplicated-image (`D`) usage convention as an optional follow-up. No behaviour, no markup.

## Edge Cases

- **Vite does not template `index.html`.** `impact-analysis.md` states this explicitly. A `<script type="application/ld+json">` in `index.html` **cannot import from `src/`**. Static literal = duplicated data that drifts. In-app injection = single source, but crawlers that do not execute JS never see it. **This is the central trade-off of W4.3. Pick one, record the reasoning, and note the drift risk if you choose the literal.**
- **A build-time plugin could inject it** — but that is build tooling, and OOS-6 excludes prerender tooling. A tiny Vite plugin for a JSON-LD transform is arguably not "prerender", but **it is a new build dependency. Do not add one without explicit approval.**
- **`lang="pt-BR"` on an English-language site.** `index.css:49`'s `:lang(pt-BR)` selector then matches nothing and the rule is dead. **Check the actual copy language first.** If the site is English, the fix is to change `:lang(pt-BR)` to match the real `lang` value — that is a CSS change inside W4.9's scope, and it changes which elements a rule applies to. Verify no visual change results.
- **Changing `lang` to `en` would be a copy-affecting, site-wide decision.** It is not this task's call. If the site is English, the correct minimal action is to make `:lang()` consistent with whatever `lang` is declared — **not** to change the declared language. Escalate if a genuine mismatch exists.
- **`me.webp` is both duplicated (D) and content-bearing (B).** This is the trap in W4.6. `AboutMe.tsx:10` is the content-bearing usage; the 14 card instances are duplicates. **A per-asset classification will get this wrong.** Audit per usage site.
- **`github.svg` and `linkedin.svg` are duplicated across all 14 cards** — so 28+ instances may share one asset. If any single card's icon is meaningful (e.g. only one GitHub link points somewhere real), that instance needs a descriptive alt even though the asset is duplicated. Verify `iconsData.ts` for per-entry URLs.
- **`lnkd.svg` is content-bearing** per the plan — so at least one LinkedIn icon is a real link. Do not blanket-decorate all LinkedIn icons.
- **Alt text affects SEO, not just a11y.** Overly keyword-stuffed alt text is a penalty risk; empty alt on a meaningful image loses ranking signal. `feasibility.md` requires alt text be *derived from existing copy* — which naturally avoids keyword stuffing.
- **`aria-hidden="true"` on a focusable or linked image removes it from the a11y tree** but leaves it clickable — a keyboard user gets an unlabelled link. If a duplicated icon is inside a link, use `alt=""` **without** `aria-hidden` so the link still has an accessible name from surrounding text.
- **JSON-LD inside `<body>` vs `<head>`.** Google accepts either, but the block is conventionally in `<head>`. TASK-18 populated `<head>`; verify where the script actually lands.
- **Trailing commas or a stray `</script>` inside a JSON string** breaks the block silently. Validate the parsed JSON, not just the presence of the tag.
- **`@id` cross-referencing** between `Person` and `WebSite` must be consistent, or the graph is two disconnected nodes.
- **A `Person` JSON-LD with a `sameAs` pointing at a 404 or a wrong profile** is worse than omitting it. Verify each URL.
- **`index.html:2` and TASK-18's `:3-8` are adjacent lines.** A merge that rewrites the head can silently revert the `lang` fix or vice versa. Re-verify both after the merge.
- **`seo.ts` is a new module in a `src/data/` directory that TASK-09/TASK-10 shaped.** Confirm the export style and naming match the established convention (named exports vs default export) before adding.
- **OOS-5: no asset or content redesign.** This task adds no images and rewrites no visible copy.

## Implementation evidence (2026-10-22)

- **W4.3/W4.14:** `index.html` has a head JSON-LD script placeholder. This limited text-constant extraction is the sole `data.ts` change.
- **W4.6 D/B per rendered site:** `AboutMe`'s me.webp uses the existing descriptive `image.alt` (B); the 15 `DefaultCard` image occurrences (11 distinct assets: ifma, maratona, voxy, dio, solyd, api, buletin, buzzfeed, angular, bokumon, shoes) are D because each card has a heading/title naming the content, and render `alt="" aria-hidden="true"`. The four icon-only Contact menu links are B, with descriptive platform-name alt from existing platform names (not hidden); the unlinked section menu icons are D, `alt="" aria-hidden="true"`. Menu logo retains a descriptive `Renan Fellipe` alt from existing title. The comment in `iconsData.ts` records optional D/B follow-up without changing its non-Contact icons' data.
- **W4.9:** The existing document language was already `en`; the existing CSS has no `:lang()` rule. Keeping English matches the predominantly English body copy and preserves all selector behavior (there was no selector to change). Built HTML's `lang="en"` comes from `seo.ts`; `og:locale` remains `en_US`.
- **Source-only checks:** `npm run build` passed with three pre-existing mixed static/dynamic import warnings. A Node assertion parsed built JSON-LD with `JSON.parse`, verified both graph nodes and author `@id`, original four `sameAs` URLs, robots sitemap, canonical/OG/Twitter origin, lang, metadata assets, and no unreplaced tokens. No new a11y errors. Dev middleware was source-reviewed but not exercised by a server under NO BROWSER/NO testserver.
